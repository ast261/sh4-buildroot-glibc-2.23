# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Buildroot fork that builds a complete embedded Linux firmware image for the **IDL4K** board (Inverto Digital Labs, STMicroelectronics STx7108 SoC, DVB-S2 satellite receiver) **including the sh4 cross-toolchain from source** in a single `make` invocation.

`configs/idl4k_defconfig` drives everything: it first builds the sh4 toolchain (glibc 2.23, GCC 15, binutils 2.45, GDB 16 — vendor tag `idl4k`, cross binaries named `sh4-idl4k-linux-gnu-*`), then uses that toolchain to build the Linux kernel and rootfs packages. The toolchain is also available as an SDK tarball via `make sdk`.

Component versions pinned for hardware/ABI compatibility:
- Kernel: 2.6.32.42 (STMicroelectronics stm24_0208 branch)
- Glibc: 2.23 (kernel headers 2.6.32.42, no ≥ 3.2 requirement)
- GCC: 15 / binutils: 2.45 / GDB: 16

## Build commands

```bash
make idl4k_defconfig             # Apply configs/idl4k_defconfig → .config
make olddefconfig                 # Refresh .config after an upstream merge
make menuconfig                   # Interactive config
make                              # Full build (toolchain + kernel + rootfs)
make sdk                          # Package toolchain into output/images/sh4-idl4k-linux-gnu_sdk-buildroot.tar.gz
make <pkg>-rebuild                # Rebuild one package, e.g. glibc-rebuild, gdb-rebuild
make <pkg>-dirclean               # Wipe one package's build dir
make savedefconfig BR2_DEFCONFIG=configs/idl4k_defconfig
```

Toolchain output lands in `output/sh-sh4--glibc--stable/` (set via `BR2_HOST_DIR`). The `sdk` target produces a relocatable tarball; run the bundled `relocate-sdk.sh` after unpacking to patch hardcoded paths.

Final firmware images land in `output/images/` — notably `idl4k.bin` (kernel) and `idl4k.scr` (U-Boot boot script), generated by `board/idl4k/post-build.sh`.

`.config` is gitignored — it is generated locally from the defconfig.

## Fork-specific files

Almost everything is upstream Buildroot. The fork's delta lives in:

- `configs/idl4k_defconfig` — the single canonical config: builds the sh4 toolchain (glibc 2.23, kernel headers 2.6.32.42, GCC 15 / binutils 2.45 / GDB 16) then the full firmware image (Linux 2.6.32.42, initramfs rootfs, board overlays).
- `package/glibc/2.23/` — glibc 2.23 with 33 backported security/build-fix patches enabling compilation under GCC 6–15:
  - Patches 0001–0031: CVE fixes and GCC 6–10 compatibility.
  - Patches 0032–0033: fix `MAKEFLAGS` corruption and an empty-recipe restart loop introduced by GNU make ≥ 4.4.
  - Do not upgrade glibc; the legacy 2.23 ABI is the whole point.
- `package/glibc/glibc.mk` / `glibc.hash` / `Config.in` — pin glibc to 2.23 (tarball, not git); drop the kernel-headers ≥ 3.2 constraint (glibc 2.23 has no such minimum).
- `package/gdb/16.3/0999-sh4-hack.patch` — hard-codes `sh4`/`GNU/Linux` arch/osabi in `regdat.sh` and changes the default tdesc register type to `uint32`. Required for remote debugging on sh4 where the architecture isn't auto-detected by the gdbserver protocol.
- `package/gdb/16.3/1000-gdbserver-ptrace-write-fallback.patch` — gdbserver falls back to `PTRACE_POKETEXT` when `/proc/PID/mem` writes fail (Linux < 3.2 / STx7108 kernel: `pwrite64()` into text pages returns `EPERM`).
- `package/gdb/16.3/1001-gdbserver-ptrace-read-fallback.patch` — symmetric read fallback using `PTRACE_PEEKTEXT`. Same root cause as 1000.
- `toolchain/toolchain-buildroot/Config.in` — removes the `glibc needs kernel headers >= 3.2` comment/constraint (not applicable at glibc 2.23).
- `board/idl4k/` — board customizations for the firmware image build:
  - `post-build.sh` — produces `idl4k.bin`, `idl4k.scr`, `idl4k-flash.scr` using mkimage.
  - `busybox.config`, `device_table_dev.txt`, `u-boot/`, `rootfs/` — overlay with SysV init scripts, proprietary DVB-S2 kernel modules (`axe_fe`, `axe_dmx`, STAPI), pre-compiled shared libraries (boost, glib for glibc 2.23), application binaries.

## CI

`.gitlab-ci.yml` drives a two-stage pipeline: it first generates a full CI config from `support/misc/gitlab-ci.yml.in`, then builds. The base Docker image is `buildroot.org/buildroot/base:20250218.2110`.
