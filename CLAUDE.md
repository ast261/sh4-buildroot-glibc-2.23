## What this is

A Buildroot-based embedded Linux distribution for the **IDL4K** board (Inverto Digital Labs), targeting the **STMicroelectronics STx7108** SoC (SH4 little-endian architecture). It produces firmware images for a DVB-S2 satellite receiver set-top box.

## Build commands

```bash
make menuconfig          # Interactive configuration
make                     # Full build
make <package>           # Build a single package
make <package>-rebuild   # Force rebuild of a package
make <package>-dirclean  # Clean and rebuild a package from scratch
make list-defconfigs     # List available board configurations
```

The build output goes to `output/`. The final images land in `output/images/` — notably `idl4k.bin` (kernel) and `idl4k.scr` (U-Boot boot script), generated by `board/idl4k/post-build.sh`.

## Architecture

### Toolchain

The build uses an **external precompiled toolchain** (not built from source). It is downloaded from GitHub (`ast261/sh4-buildroot-glibc-2.23`) and staged into `output/sh-sh4--glibc--stable/`. Cross-compiler prefix: `sh4-idl4k-linux-gnu-`.

Intentionally old versions for hardware compatibility:
- Kernel: 2.6.32.42 (STMicroelectronics stm24_0208 branch)
- Glibc: 2.23
- GCC: 10.3.0

### Board customizations (`board/idl4k/`)

- `post-build.sh` — Runs after the build; produces `idl4k.bin`, `idl4k.scr`, `idl4k-flash.scr` using mkimage.
- `busybox.config` — Custom BusyBox feature set.
- `device_table_dev.txt` — Static device nodes for the target rootfs.
- `u-boot/` — U-Boot boot scripts (source `.script` files; compiled to `.scr` by post-build).
- `rootfs/` — Rootfs overlay merged on top of the build output. Contains:
  - SysV init scripts (`/etc/init.d/`) for networking, SSH, NTPd, minisatip, oscam
  - Pre-built proprietary kernel modules for DVB-S2: AXE frontend (`axe_fe`), AXE demux (`axe_dmx`), STAPI drivers
  - Pre-compiled shared libraries (boost, glib) targeting glibc 2.23
  - Application binaries (`main_axe.out`, `load_env.sh`)
  - SSH host key generation script

### Active branches

- `main` / `master` — Upstream Buildroot tracking
- `idl4k-toolchain` — Primary IDL4K development branch
- `idl4k-toolchain-gcc{11-15}` — Variants testing newer GCC versions
- `rootfs` — Rootfs-only changes

Most IDL4K work happens on `idl4k-toolchain`.

## Key configuration

`.config` at the repo root is the active Buildroot configuration. Important settings:
- `BR2_sh4=y` — SH4 little-endian target
- `BR2_TOOLCHAIN_EXTERNAL=y` — External toolchain mode
- `BR2_TARGET_ROOTFS_JFFS2=y` — Flash filesystem image
- `BR2_GLOBAL_PATCH_DIR` — Points to custom patches including `busybox.patch`

## CI

`.gitlab-ci.yml` drives a two-stage pipeline: it first generates a full CI config from `support/misc/gitlab-ci.yml.in`, then builds. The base Docker image is `buildroot.org/buildroot/base:20250218.2110`.
